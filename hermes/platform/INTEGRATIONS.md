## 1. Regras que governam TODA integração (v1.1, inegociáveis)

1. **Um único kernel/autoridade:** o Hermes AIAgent. Nenhum runtime de outro framework é importado
   no processo do agente, e nada substitui o cérebro/turno do Hermes.
2. **Quatro formas de integrar** (aplicadas em ordem de preferência):
   - **(A) Integração de kernel** — chamar capacidade real que o Hermes *já tem* (Kanban, MCP client,
     auth, acp_adapter, plugin manager, worktrees, Web Dashboard).
   - **(B) Adapter de processo/serviço** — executar binário/CLI/serviço externo por subprocesso ou
     protocolo (nunca import lib no core), com health/scope/failover.
   - **(C) Port de padrão (clean-room)** — re-escrever o *conceito* em Python HAOS, sem copiar código.
   - **(D) Protocolo** — implementar contra a spec (MCP/ACP/A2A/ANP/LSP), usando o SDK só quando o
     upstream já o usa dentro do Hermes.
3. **Sem novas dependências no core** (política Hermes): deps pesadas (agno, graphrag, langchain…)
   entram só como serviço externo (B) ou padrão (C). O scaffold `hermes/platform` continua stdlib.
4. **Prompt-cache sagrado; extensões por Plugin → Hook → Adapter → Event → Extension;** nada de
   mutar contexto/cache do kernel.
5. **`extend, don't duplicate`:** se o Hermes (ou o scaffold HAOS) já cobre o recurso, a integração é
   *completar/envolver*, não criar paralelo (lição do D2).
