# Health agent contract

Health probes are bounded, read-only observations with `component`, `check`, `deadline`, and correlation ID. Results are `status` (`live`, `ready`, `degraded`, `failed`), `observed_at`, latency, and a short stable reason code. Probe execution has a 2-second default deadline, 32 checks per request, and no recursive dependency probing. Liveness is process-local and must not depend on optional services. Readiness includes required dependencies (policy/keyring/transport as configured); optional adapters are reported as `degraded` or an explicit optional-disabled state and do not make liveness fail. An adapter marked required must make readiness fail when unavailable, locked, or timed out. Configuration must declare whether each dependency is required or optional; there is no implicit “optional means ready” fallback.

The agent does not restart processes or mutate configuration. Diagnostic details are redacted and capped at 4 KiB. Health snapshots may omit platform-specific metrics when unavailable, but must preserve stable schema and bounded output.
